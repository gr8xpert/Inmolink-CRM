# Changelog

All notable changes to this project are documented here. Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added
- Monorepo scaffold: pnpm workspace + Turborepo with every app and package from PLAN §5.7 as a building skeleton, strict TypeScript/Biome/Vitest presets in `@inmolink/config`, husky + lint-staged, `pnpm verify` (Turbo `--affected`), stubbed root scripts for later tasks, and ADR 0001 with pinned versions. New dev dependencies: turbo, @biomejs/biome, typescript, vitest, tsdown, tsx, husky, lint-staged, @types/node; next, react, react-dom in the Next.js apps. [S0-01]
- Local stack: `docker-compose.yml` with `dev` and `test` profiles (PostgreSQL 18 + PostGIS/pgvector/pg_trgm/pg_partman, PgBouncer, two Redis instances, Meilisearch, MinIO, Mailpit, OTel collector + Jaeger), `scripts/ops/health.ts` (`pnpm infra:health[:test]`), `.env.test.example`. `pnpm dev` starts infra first. New root dev dependencies: pg, @types/pg, ioredis. [S0-02]
- Platform core: `@inmolink/platform` subpaths `config`, `logger`, `errors`, `ids`, `clock`, `crypto`, `crypto/password`, `http`; `AppError` + `ErrorCodes` in `@inmolink/contracts`; ADR 0003 (Argon2id params, AES-256-GCM envelope, rotation, HMAC). `.env.example` gains local-only `ENCRYPTION_KEYS`, `ENCRYPTION_ACTIVE_KEY_ID`, `HMAC_KEY`. New dependencies: zod (contracts, platform), pino, @node-rs/argon2. [S0-03]
- Database package: `@inmolink/db` per-role pools (`app_user`, `app_system`, `app_public`) with `withTenant`, `withSystem`, `withPublicRead`, `getPgClient`, `configureDb`/`closeDb`; `pnpm db:migrate` (advisory-locked role bootstrap with SCRAM verifiers and role-level statement timeouts, then drizzle-kit migrations as `app_owner`), `pnpm db:migrate:test`, `pnpm db:generate`. `DATABASE_URL_APP_SYSTEM` becomes optional and is refused for HTTP processes in production. New dependencies: drizzle-orm, pg (db); drizzle-kit, @types/pg, tsx (db, dev). [S0-04]
- Tenant registry and RLS: `packages/db/src/tenancy/registry.ts` (STRICT / NETWORK_READ / PUBLIC_READ tenant tables + explicit global tables), `pnpm db:rls[:test]` generates `packages/db/rls/policies.sql` (helpers, forced RLS, policies, per-table grants), applies it and runs the guard; `pnpm test:isolation` (in `verify`) runs the cross-tenant suite generated from the registry plus guard tests. App roles no longer get default table/function privileges: grants come only from `db:rls`. Root dev dependencies: @inmolink/db, @inmolink/platform, drizzle-orm. [S0-05]
- Outbox and queues: `outbox_events` (STRICT, append-only tenant table via the new registry flag `appendOnly`; nil-UUID agency for platform events) with `@inmolink/platform/outbox` (`defineEvent`, `emit` + NOTIFY in the caller's transaction, `subscribe`, lease-based dispatcher with SKIP LOCKED claims, batch 500, LISTEN wake-up + polling fallback, retries/dead-lettering, retention prune, replay) and `@inmolink/db` `listen()` over the new optional `DATABASE_URL_LISTEN` (direct connection, refused for HTTP processes in production); `@inmolink/platform/queue` (`defineJob`, `registerPool`, stable job IDs, retries/backoff, `<pool>.dead` dead-letter queues, debounce via BullMQ deduplication, per-group fair share by backlog-depth priority + Lua lease caps, same-tick enqueues batched into `addBulk`); `pnpm ops:replay-outbox`; `pnpm test:perf:root` (in `verify`, runs last). New dependencies: bullmq, ioredis, drizzle-orm (platform); zod (root, dev). [S0-06]
- Cache, rate limits, feature flags: `@inmolink/platform/cache` (read-through on redis-cache with per-process single-flight, tag invalidation by random tag versions, optional 60 s in-process LRU, `cacheKey()` builder whose branded keys always name their tenant scope, degrade-to-loader when Redis is down), `@inmolink/platform/rate-limit` (sliding-window counter in one Lua script, scopes ip/user/key/tenant, HMAC'd identities, credential rules must fail closed, Fastify plugin with 429 + `Retry-After`, IPv6 /64 buckets), `@inmolink/platform/flags` (`feature_flags` global table, `flag(ctx, key)` with per-agency overrides, cached 60 s); logger drops ioredis `command`/`args` from errors. New dependency: fastify (platform dev + optional peer, root dev). [S0-07]
- App skeletons: `@inmolink/platform/server` (`createServer` with the Zod type provider, edge-only request ids, the standard error body for `AppError`/validation/framework errors, OpenAPI with `/docs` in development, request logs without query strings; `/healthz` + single-flight cached `/readyz`; `gracefulShutdown` with a 30 s deadline; `drainHttp`), `httpEnv` (`HOST`, strict `TRUST_PROXY`, `SHUTDOWN_DRAIN_DELAY_MS`, `EDGE_REQUEST_ID_HEADER`); Fastify apps `api` (rate limits, `withCtx`), `feed-api` (`app_public` only), `realtime` (Socket.io + Redis adapter, connections refused until auth), `worker` (`WORKER_POOLS`, outbox dispatcher pool, health server); `@inmolink/core` `Ctx`/`withRequestCtx` and runtime lifecycle; contracts `ErrorBody`/`HealthBody` and codes `BAD_REQUEST`/`PAYLOAD_TOO_LARGE`/`UNSUPPORTED_MEDIA_TYPE`/`SERVICE_UNAVAILABLE`; Tailwind v4 + shadcn base (`cn`, `Button`, `theme.css`) in `@inmolink/ui` for `web` (port 3100) and `public` (3101) with `/healthz`; boot smoke test (`tests/apps`). Fixed: a pooled pg client that lost its connection while checked out crashed the process (unhandled `'error'`). New dependencies: @fastify/type-provider-zod, @fastify/swagger, @fastify/swagger-ui (platform); fastify, zod (apps); socket.io, @socket.io/redis-adapter (realtime); socket.io-client (realtime, dev); clsx, tailwind-merge, class-variance-authority (ui); tailwindcss, @tailwindcss/postcss (web, public, dev); openapi-types (platform, dev). [S0-08]
- Authentication (ADR 0004): login role `app_auth` + `withAuth()` and registry options `access: 'auth'` (global identity tables) / `authAppend` (outbox, `identity.*` platform events only); tables `users`, `auth_tokens`; `@inmolink/platform/jwt` (Ed25519 access tokens, 15 min, per audience), `@inmolink/platform/email` (smtp — Mailpit locally, SES SMTP —, resend, memory), `clientIpFromForwarded`, rate-limit scope `email`, config sections `emailEnv`, `webUrlEnv`, `authSignEnv`, `authVerifyEnv`, `authSessionEnv` (production refuses dev and committed example keys/secrets) and `DATABASE_URL_APP_AUTH`; core module `identity` (sign-up, email confirmation with password, login check, password reset with single-use 60-minute links, access tokens, session re-check, `identity.sendAuthEmail` job, EN/ES emails) and `AuthCtx`; identity contracts and codes `INVALID_CREDENTIALS`/`EMAIL_NOT_VERIFIED`/`TOKEN_INVALID`/`SESSION_REVOKED`; api `requireSession` + `GET /v1/me`; realtime handshake JWT + origin allowlist; worker `email` pool; web Auth.js login/sign-up/confirm/forgot/reset pages (EN/ES) and `/session/token`; `Input`/`Label` in `@inmolink/ui`; `@inmolink/i18n` auth catalogs; `@inmolink/core/modules/*` and `@inmolink/db/schema/*` subpath exports; `pnpm test:e2e` (Playwright). New dependencies: jose, nodemailer (platform); @types/nodemailer (platform, dev); next-auth 5.0.0-beta.32 (web); drizzle-orm, zod, @inmolink/i18n (core); @playwright/test (root, dev). [S0-09]
- Observability: `@inmolink/platform/telemetry` (OpenTelemetry traces → OTLP collector → Jaeger, parent-based ratio sampling without BullMQ housekeeping roots, query strings stripped from spans; Prometheus `/metrics` per app on a private port; Sentry errors with release, environment, service and request-id tags, no request data) and the `telemetry/register` preload (`node --import`) that patches http, fetch, pg and ioredis. Per-route RED histogram `http.server.request.duration` and route-named server spans in `platform/server`; trace and span ids in every log line; outbox rows carry `trace_parent` (migration 0003) so delivery continues the emitter's trace; BullMQ jobs continue it via bullmq-otel (job metrics too). Next.js `instrumentation.ts` in web. Grafana stubs in `infra/grafana/dashboards/`. Hardening from review: client `traceparent`s re-sampled on internet-facing apps, no baggage, no Sentry trace headers on outgoing calls, client IPs/job results/emails stripped from spans and Sentry messages; production config requires an explicit sample ratio, a real `RELEASE`, an https DSN and a private `METRICS_HOST`. `withSystem(…, { routine: true })` logs at debug (outbox dispatcher); `configureCache({ commandTimeoutMs })`. New dependencies: @opentelemetry/* (api, sdk-trace-node, sdk-metrics, resources, core, semantic-conventions, exporter-trace-otlp-http, exporter-prometheus, instrumentation, instrumentation-http/-pg/-ioredis/-undici), bullmq-otel, @sentry/node (platform); @opentelemetry/api in db and core keeps a single drizzle-orm peer variant. [S0-10]
- i18n foundation: `packages/i18n` locale config (`locales.json`, UI and content locales), Intl formatters, bundled catalogs with EN fallback and an ICU `translator`, `pnpm i18n:check` / `pnpm i18n:draft`; next-intl locale-prefixed routing (`proxy.ts`, `app/[locale]`) in `web` and `public`; auth pages on `getTranslations`; auth emails link to the user's locale. New dependencies: `next-intl` 4.14.9 (web, public), `use-intl` 4.14.9 (i18n). [S0-11]
- Module scaffolder and boundaries: `pnpm gen:module <name> [--no-routes]` (PATTERNS §1 module files, policy + test, schema and contracts files in their barrels, api route plugin registered); `.dependency-cruiser.cjs` rules (apps thin, module internals private, own schema only, layering, no cycles/unresolvable/undeclared imports) run by `pnpm check:boundaries`; `pnpm test:boundaries` (generated module + planted violations in a sandbox copy); both in `verify`. Root dev dependencies: dependency-cruiser 18.5.0, @inmolink/app-web, @inmolink/app-public, @inmolink/ui, @inmolink/sdk (so `--affected` reaches the boundary tasks). [S0-12]
- E2E sign-up test waits for the second confirmation email before following the link (the fresh link invalidates the first; the test raced it). [S0-10]
